# 第三章：指標如何變成風險分數

## 3.1 現行 `mapToScore()` 真正執行方式

目前 `V70_2.html` 的實際可執行邏輯是：

1. 先依 T0、T5、T10 做分段線性映射，得到 0～10 的底稿分數 `s`。
2. 再執行：

```text
applyGamma(s, gamma) = (s / 10)^gamma × 10
```

程式最後四捨五入到小數一位。

若 T10 > T0，代表數值越高風險越高；若 T10 < T0，代表數值越低風險越高。

## 3.2 估值額外做中線收斂

QQQ／SPY／VT 三個估值指標經 Gamma 後，再執行：

```text
risk_valuation = 5 + 0.7 × (risk - 5)
```

目的：避免估值單一因素把整體 Macro 分數拉得過度極端。

## 3.3 舊 HTML 底部「A/B/C Gamma 工程說明」與實際程式的差異

目前 HTML 底部文字提到：

- A 類使用 `piecewiseGamma`
- B 類使用 `lightGamma`
- C 類使用 `veryLightGamma`

但目前可執行程式實際只有統一的 `mapToScore()`＋`applyGamma()`，以及估值額外的 α=0.7 中線收斂；**並沒有真正定義或呼叫 `piecewiseGamma`、`lightGamma`、`veryLightGamma` 函式。**

因此本白皮書以「實際可執行程式」為準。若未來真的要導入 A/B/C 三種 Gamma 函式，需另開模型版本並回測，不得只改說明文字。

## 9.4 V70.2 旋鈕 B：股債戰術偏移 Tactical Tilt

在非停車／非熔斷情況下，先保留子彈池 `C`，剩餘可部署資金：

```text
D = 100 - C
```

再以客戶已核准的 `S0/B0` 為中心做戰術偏移：

```text
S_tactical = S0 + T
B_tactical = B0 - T
```

其中：

```text
-10 <= T <= +10
```

一般情況以 ±5 個百分點為主要微調；只有多項總經訊號一致、且沒有 CAP／信用／流動性否決時，才允許到 ±10。

### T 的基本方向

| Macro 狀態 | 基本 T | 意義 |
|---|---:|---|
| mSafe >=70 | +5 | 偏股票，但仍受估值／信用／流動性否決 |
| 55～<70 | 0 | 以客戶已核准S0/B0為主 |
| 40～<55 | -5 | 偏防守；若債券環境差，防守資金優先去 SGOV 而不是機械加債 |
| <40 | 不使用一般 T | 進入停車覆蓋 |

## 9.5 Tactical Tilt 必須接受總經否決

### 股票加碼否決

即使 mSafe >=70，出現以下情況時，`T>0` 取消：

- 估值群組風險進入高檔
- 信用群組進入高檔
- 流動性群組進入高檔
- Panic／Crisis／Recession 任一 CAP 已啟動

目前正式 HTML 的 deterministic 實作門檻固定為：**七群組 0～10 風險分數 `>=7` 視為高檔**。這只是把白皮書原本的「極高／明顯惡化」工程化成可重現門檻，不新增新聞主觀分數。

### 債券加碼否決

`T<0` 代表相對增加債券；目前正式 HTML 在下列任一條件成立時，取消一般負偏移、回到核准S0/B0基準：

- `bScore < 5` 或資料無效
- Inflation 群組風險 `>=7`
- Rates/Curve 群組風險 `>=7`
- Credit 群組風險 `>=7`

若「股票不佳、債券也不佳」，正確答案仍是 **增加 SGOV 子彈池**，不是機械把股票換成債券。

### 強化債券偏移條件

目前正式 HTML 僅在 `cap_crisis = 100`（危機 CAP 未啟動）且：

```text
bScore >= 7
Inflation < 7
Credit < 7
Rates/Curve < 7
```

才額外把 `T` 再降低 5 點；總偏移下限固定 -10。

### 衰退情境

若 Recession CAP 已啟動、通膨沒有同步失控、bScore 又有吸引力，允許向債券方向偏移；若屬停滯性通膨，則優先增加 SGOV，不應以「衰退」兩字自動重押債券。

## 9.6 最終公式

非停車／非熔斷：

```text
D = 100 - C
Srel = clamp(S0 + T, 0, 100)
Brel = 100 - Srel

finalStock = D × Srel / 100
finalBond  = D × Brel / 100
finalDryPowderSGOV = C
```

三者總和必須精準等於 100%。

### 例：核准S0/B0=60/40；V70.2防守

```text
S0/B0 = 60/40
mSafe = 48 → C=20
基本 T=-5
Srel/Brel = 55/45
D=80

股票 = 80×55%=44%
債券 = 80×45%=36%
子彈池 SGOV = 20%
```

這表示客戶核准的長期基準仍是60/40，只是目前Macro暫時採44/36/20戰術配置。

# ⚖️ 04｜評估現在如何買賣與調整

版本：v1.0.0｜日期：2026-10-24
狀態：選單執行規則已建立；既有程式與待接項目如下。
依據：[十一項完整對照](../Family_十一項選單與完整程式鏈.md)（核對基準 commit 53956f60ba09da3320861d7057e1fff42cc159ce）。本規則為操作路由，不改寫投資引擎規則。

## 觸發與第一句

評估已有資產的續抱、買賣、換標的與SGOV運用，不以有新增資金為前提。
先說：「好，我先查看您的持倉與目標配置，評估現在適合維持或怎麼調整。」

## 輸入及入口

同一人的目前持倉、正式目標、各帳戶資金（已結算／未結算／預留）、掛單、保留部位、上游V70結果及股票／債券／技術／總經資料、日期及來源。
入口：`系統工程/Family/W5/family_runner.py → FamilyRunner(repo_path, context_provider=...).analyze(request)`。
需要完整request、native_bundle、可信context及版本／來源綁定，不能只傳DB檔名。目標需變更時先轉 [03_目標配置調整.md](03_目標配置調整.md)。

## 後續整串程式

以下檔案除特別註明均位於`系統工程/Family/W5/`：

1. `family_boundary.py`核對身分及輸入。
2. 來源綁定：`target_source_bridge.py`、`bond_target_bridge.py`、`position_source_bridge.py`；`funding_bridge.py`、`macro_source_bridge.py`、`v70_source_bridge.py`；`stock_source_bridge.py`、`bond_source_bridge.py`、`family_technical_bridge.py`。
3. `c7_engine.py → work7.asset_framework.run_asset_framework_integration()`整合資產框架；該work7位於C正式Runtime。
4. `native_pipeline.py → run_native_pipeline()`組織下列分支與整合。
5. 股票：`stock_engine.py` → C8C9 Work4.build_v82_runtime_input → V82.validate_and_bind_funding → tactical_cap → evaluate_core_rule_state → select_deployment_mode → resolve_deployment_stage → calculate_position_gap → build_buy_execution_plan → assemble_stock_output。
6. 債券：`bond_engine.py` → C8C9 Work5.build_v75_runtime_input → V75.validate_v75_run_input → predicates及work3狀態 → evaluate_step10 → build_decision → proportional_scale_decisions → calculate_v75_undeployed_to_sgov → assemble_final_snapshot → evaluate_runtime_ready → C8C9 Work5.consume_v75_runtime_ready。各步按實際資格與資料分支執行。
7. `funding_bridge.py`＋`funding_guard.py`＋C8C9 Work6：核對帳戶隔離及股票、債券合計部署額度。
8. `sgov_bridge.py`＋C8C9 Work7：核對SGOV保留／等待部署用途、金額及重複計算。
9. `permission_bridge.py`＋C8C9 Work8：處理指定保留部位，區分風險訊號與客戶動作。
10. C8C9 Work9.build_unified_deployment：形成統一結果。
11. `mentor_bridge.py → explain_native()`＋`reason_catalog.json`：保留動作、來源、日期與正式理由，GPT再口語化。

共用相依：`runtime_loader.py`、`verify_dependencies.py`載入與驗證；`recovery_bridge.py`管理重試／重用；`tactical_budget.py`戰術額度；有C7結果時`target_units.py`投影目標單位。
C8C9位置：`系統工程/C-配置決策引擎＋Mentor整合/正式Runtime/C8C9_RUNTIME/`。股票及債券底層套件為`livingwater_v82_runtime`與`v75_runtime`，依既有loader及鎖定相依定位，不自行拼湊副本。

## 輸出與待接

使用同一client_id、run_id的正式結果，呈現逐檔動作、理由、原有金額／條件與日期。等待就說明等待條件；來源衝突交回接口處理，GPT不選一套自編結論。
V70是上游輸出，v70_source_bridge只綁定／驗證，不代表Runner會自動重算V70。
已確認的股票函式包含買進計畫；完整賣出／換股數量、資金釋放及成交後再投入鏈待核對。禁止將買進計畫當作完整換股引擎。
現有核對版本為ISOLATED_TEST_STAGING、production=HOLD、trade_action=NO_TRADE；explain_native輸出execution_advice_allowed=False。依實際執行狀態呈現，不因選單文字變成正式交易指示。
待接：完整本人資料映射、賣出換股鏈及功能驗收。分析結果不直接寫成已成交持倉。

## 共通執行約定

- 先用一兩句話說明本次目的，再於同一輪執行；工具間隙回報實際進展。有必要缺項才提問，保留已選需求。
- 依專案既有方式檢查登入與本人身分。私有DB位置從既有資源設定取得；此文件不放帳密或私人資料。
- 本次需要時才讀本規則與相依。每輪固定一個已確認Git commit取得規則、程式與相依；同版已載入可重用，避免混用不同版本。資料另按日期及正式更新需求核對。
- 程式提供投資判斷；GPT只調整語氣、排版與用詞，保留數字、理由、條件、動作及日期。未知理由代碼依正式說明補齊，不自行推論為投資建議。
- 執行前查看入口支援狀態；程式回傳缺資料、衝突、HOLD或測試狀態時如實呈現。工具失敗或限流停止自動重試，簡述完成處與待辦。
- 修改資料需走已接妥的正式handler與Coordinator.update；保留分析建議、掛單、成交的區別。未保存就標示待保存，成交後才更新實際持倉。
- 本次文件建立不代表新功能上線。待接項目由Family中PM接續定位既有成果、接線及驗收，避免另造重複引擎。

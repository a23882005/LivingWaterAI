# V70產出-客戶名字

> **正式命名規則：** `V70產出-<客戶名字>.md`  
> 例如：`V70產出-mou.md`、`V70產出-Joseph.md`。  
> 本檔是格式契約／範本；實際客戶檔由 `V70_2.html`／未來API每次運算產生，保存於該客戶專案資料夾或由專案系統維護的客戶工作區。

## 定位

本檔固定承接同一輪：

1. Mentor 已核定的長期 `S0/B0` 與客戶人生情境 metadata（`lifeStageCode`／`lifeStageLabel`）。
2. V70 模型實際使用的原始總經數字與風險分數。
3. V82／債券V75／客戶報告仍需要的補充 Macro Snapshot。
4. 最近 1～2 日重大總經／政策／市場新聞。
5. V70 的 `mSafe`、CAP、`bScore`、七群組與 `T/C`。
6. 今日股票／債券／`V70_ORIGINAL_DRY_POWDER` 戰術額度。
7. 本輪 `run_id`（建議欄位，用於跨 V70／V82／V75／客戶專案串接；舊資料沒有 run_id 仍合法）。

> **V70只輸出自己的原生等待資金 `V70_ORIGINAL_DRY_POWDER`。最終 `SGOV_DRY_POWDER_BUCKET` 由客戶專案彙總 V70＋V82＋V75 未部署額度後形成。**

## 強制欄位

### A. 身分與新鮮度
- 客戶名字
- `lifeStageCode`（Mentor 人生情境代碼；僅作下游 metadata，不參與 V70 債券拆分）
- `lifeStageLabel`（Mentor 人生情境名稱；與 `lifeStageCode` 成對保存）
- `run_id`（建議格式 `RUN-YYYYMMDD-HHMMSS`；時間戳仍為必要欄位）
- V70版本
- 共用資料截止時間（As-of）
- 產出時間（台灣時間）
- 每項可得資料的日期與來源
- 缺失／過期警示與待補項目（至少檢查預設客戶名、As-of、新聞、補充 Macro Snapshot、主要輸入資料日期、有效股債金額度）

### B. Mentor × V70
- `S0`、`B0`
- `T`
- `C`
- 今日股票%、債券%、`V70_ORIGINAL_DRY_POWDER`%
- Parking／Emergency／一般 Tactical 模式

### C. V70 Macro
- V70 所有模型輸入原始值
- 各指標 Risk 0–10
- 七大風險群組
- Accelerator
- `mSafe_raw`
- `cap_panic`／`cap_crisis`／`cap_recession`
- `mSafe_final`
- `bScore`
- H-Score 聚合值（QQQ／SPY／VT，可選；僅作資訊輔助，不直接決定配置）

### D. 下游共用補充 Macro Snapshot
至少按本輪需要保留：PPI／Core PPI、CPI／Core CPI、PCE／Core PCE、2Y／5Y／10Y／20Y／30Y、Real Yield、5Y／10Y Breakeven、5y5y、HY／BBB／A／IG OAS、VIX、MOVE、SOFR／OIS、Repo、Treasury流動性／供給、DXY、WTI／Brent、GDP、NFP、失業率、薪資、消費等。

未納入 V70 七群組公式的資料仍可放在本區，供 V82、債券V75 與報告使用。

### E. 重大新聞
固定保存最近 1～2 日真正重要的 Fed、Treasury、通膨、信用／流動性、能源、地緣政治、AI／半導體及會影響客戶持倉的重大事件；每則至少保留日期、核心結果、影響與來源。若由 API 注入結構化新聞，`date/title/summary/impact/url/source` 必須原樣保留；UI 文字欄只能作鏡像或人工覆寫，不得造成來源欄位遺失。

## 下游權責

### V82
讀取本檔作為共用 Macro／新聞／股票戰術總額度；仍須自行依基本面、估值、價格地圖、技術、多時間框架、Hard Gate、Runaway Down與客戶目標完成率作逐檔第二次判斷。

### 債券V75
讀取本檔作為共用 Macro／新聞／債券戰術總額度，並讀取 `lifeStageCode`／`lifeStageLabel` 以套用債券V75正式的人生情境規則；美國／台灣債券子桶與逐檔比例仍完全由債券V75決定。之後再依 Fed、完整殖利率曲線、通膨、期限溢價、信用、流動性、Treasury供給、久期、ETF結構與技術作逐檔第二次判斷。

### 客戶報告／HTML
以本檔作同一輪 Macro／新聞／戰術股債金比的共用事實來源，再合併 V82 與債券V75 的逐檔結論。客戶頁不得顯示內部檔名、debug或分數工程細節。

## 資料完整度規則

只有當客戶身分、`lifeStageCode`／`lifeStageLabel`、As-of、重大新聞（日期／核心結果／影響／來源完整）、補充 Macro Snapshot（可得指標具日期／來源）、V70主要輸入資料日期與有效股債金戰術額度都可辨識時，才能標示為「可作本輪共用 Snapshot」。缺任何一項時，檔內必須列出待補項目；下游可補抓／建立較新 Delta，但不得把不完整狀態誤標成完整。

Macro input metadata 與補充 Snapshot metadata 必須採合併保留；`indicators`／`macroInputs` 兩種別名需正規化合併，後一次資料注入不得無意刪除或遮蔽已存在的資料日期／來源。


## Dry Powder 分帳契約

V70 本輪輸出的 `C` 只對應：

> `V70_ORIGINAL_DRY_POWDER`

客戶專案在 V82／債券V75 完成本輪判斷後，再依：

> `SGOV_DRY_POWDER_BUCKET = V70_ORIGINAL_DRY_POWDER + V82_UNDEPLOYED_TO_SGOV + V75_UNDEPLOYED_TO_SGOV`

形成最終待部署 SGOV 子彈。`CASH_DRY_POWDER_BUCKET` 另記客戶實際可部署現金；`TOTAL_DRY_POWDER = SGOV_DRY_POWDER_BUCKET + CASH_DRY_POWDER_BUCKET`。

`SGOV_BOND_BUCKET` 永遠屬正式債券配置，不能與上述子彈重複計入。

## 新鮮度規則

`V70產出-<客戶>.md` 是本輪 Snapshot，不是永久市場事實。若產出後發生重大數據、Fed、Treasury、政策、戰爭／地緣政治、能源、信用、流動性或公司／產業重大事件，下游正式判斷前必須先更新本檔，或明確建立較新的 Delta，舊資料不得直接覆蓋新事實。

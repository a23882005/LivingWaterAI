## 二、外部五大驗收證據與驗收方法
| 類別 | 獨立驗收步驟 | 最低可核查證據 | 未達標處置 |
| --- | --- | --- | --- |
| public HTTPS MCP | 從經核准的外部網路及不同主機，對公開 HTTPS MCP 執行連線與 TLS 驗證；檢查憑證、端點、拒絕重新導向等 | 端點環境 ID、UTC 時戳、可重現請求 ID、TLS 結果、經遮罩的回應摘要 | HOLD |
| 真實 OAuth / resource binding | 用兩個不同的測試身分分別登入，查核 issuer、audience、scope、subject、有效期與伺服器端資源綁定；測試錯誤 token 與不同 resource | IdP 設定識別、經遮罩的 identity claims、拒絕記錄、測試執行證明；不得存取 token 原文 | HOLD |
| 伺服器端 tenant binding | 核對 API 不以用戶自己填的 client_id 或檔名取得跨 tenant 權限；涵蓋 API、資料庫查詢與文件檢索路徑 | 同身分合法讀取 200、越權讀取 403 的請求/稽核關聯 ID、測試環境證據 | HOLD |
| 雙向跨客戶隔離 | 經正式核准後，使用分離的雙方測試身分執行 A→A、B→B 合法讀取及 A→B、B→A 越權讀取；含改路徑、改 ID 與重播測試 | 四個方向的可核查結果與 audit 事件對照；不可放真實客戶持倉、個資 | HOLD |
| 獨立 audit 與治理簽核 | 由不同於開發者的安全審查者，在留存系統中重新打開拒絕事件、核對 SHA-256 與簽章信任錨；完成有權審查流程 | 持久化證據位置、每件原始檔雜湊、獨立保管證明、審查者授權與帶簽章的審查紀錄 | HOLD |

上述五類為正式驗收必備項目；第三方、環境與身分的核准，以及資料保管設計必須先行完成，不可直接拿真實 Joseph/mou 個人資料測試。

## 三、證據包最低欄位
每個條件必須提供：evidence_category、environment_id、test_case_id、UTC observed_at、sanitized_request_id、result、evidence_url、sha256、witness_role、provenance、storage_retention、reviewer_decision。
證據原始檔必須從經核准的獨立保管位置重新讀取、計算 SHA-256 並交叉比對。格式正確、網址存在、摘要一致、多人聲明一致，均不足以代表證據真實或 Gate A PASS。
禁止將 OAuth token、API key、cookie、Authorization header、私鑰、完整客戶資料或未遮罩 audit 內容寫入 GitHub。
